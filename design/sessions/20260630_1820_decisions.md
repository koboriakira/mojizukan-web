## 1. brief からの変更点

ブリーフの前提と、現行リファレンス（`design_handoff_mojizukan/README.md` ＋ 現行プロトタイプ）の実態が乖離していた点を、**現行リファレンスを正**として整理した。

- **「おまかせモード（親が仕込み→子がなぞって発見）は未実装／現在は直接入力→生成のシンプルなフロー」** という brief 記述は古い。現行は **みつける（おまかせ発見）が実装済み**で、保護者が「ひみつの ことば」を `seeded[]` に仕込み、子どもが伏字の「？」をなぞって発見する導線が中心。本設計はこの実態に合わせた。
- **ドメイン語彙を ADR-0001 に整合**：本書「再はっけん」は ADR の **再発見 / rediscovery**（既にずかんにあることばを再度生成）に統一。**はっけん**＝ずかんに未登録のことばを登録する行為（みつける・たんけん 両経路で発生）。**共有キャッシュはインフラ層**で、はっけんの可否ではなく速さのみに影響。**ことばあつめ → おはなし は一方通行**（Published Language）。チケット判定は アカウント・経済ドメインの `canSpend`/`spend` に集約。
- **本番モデルの非対象**（ADR-0001 の Consequences）：emoji・カテゴリ分類・「プリセット語」概念は本番では持たない（プロトの名残）。コード名は `collected→zukanWords`／`discovered→hakkenWords`／`screen:'write'→'trace'` にリネーム予定。プロトタイプの該当実装は暫定。
- **チケット経済の「再はっけん（同じ言葉で再生成）はチケット不要」** は brief で要件化されているが、UI 入口が存在しなかった。本設計で **しょうさい画面からの再生成（チケット不要）** を新設・実装した（下記④）。
- **おはなし接続** は「集めた言葉→おはなし作成への導線」が brief 要件。基本導線（ライブラリ起点）に加え、**発見直後のショートカット**を追加実装した（下記⑤）。
- 課金原則を明文化：**子ども画面に金額・購入を出さない**（402＝残高0でも閲覧は維持、生成のみブロック）。購入・残高管理は保護者ゲートの先。

## 2. ユーザータイプ別フロー

### A. 未ログイン（ゲスト）
1. ホーム（入口。たんけん／おはなしに 🔒 バッジ）
2. **みつける**（ゲスト可）→ みつける振分（出題1語抽選）
3. なぞり書き（発見モード・正体は伏せる）
4. はっけん中（生成演出。キャッシュで速さが変わる）
5. のったよ（絵・名前・説明が判明）→ ずかん（ゲスト可・点線の登録促し）
6. たんけん／おはなしを押した場合 → 登録シート（機能別コピー）→ 認証完了で目的機能へ自動遷移（`_afterAuth`）

### B. ログイン済み（みつける）
1. ホーム → みつける振分（`seeded` 優先 → 未取得プリセット）
2. なぞり書き → はっけん中 → のったよ
3. 「つぎも かく」でループ／「ずかんを みる」へ
4. プール枯渇時 → 復習モード（既得語を再なぞり）または「ぜんぶ みつけた」画面（保護者へ相談）

### C. ログイン済み（たんけん）
1. ホーム → たんけん（50音で言葉を作る）
2. `classifyTanken` 判定
   - NG／重複 → エラーメッセージで差し戻し
   - 辞書語 → 無料でなぞり書きへ
   - 新語 → 残高・本日回数チェック → OK ならなぞり書き → はっけん中 → のったよ
3. 残高0／回数超過 → たんけんおしまい画面 → みつける／ホームへ回遊

### D. 再発見（同じことばで再生成・rediscovery）
1. しょうさい（登録済みの語）
2. 「🎨 べつの えに する」→ 再生成 確認シート（ブリーフ前提では**チケットを使わないことを明記**。キャッシュヒット時の消費可否は ADR-0001 で未確定）
3. はっけん中（再生成演出。同スタイルは共有キャッシュ即返却／別スタイルは新規生成）
4. しょうさい（新しい絵で更新。ずかん件数は増えない）
5. 失敗時 → 元の絵を保持し「もういちど」（消費なしを維持）

### E. おはなし接続
1. 基本：ずかん／ホーム → おはなしホーム（ライブラリ）→ ことばえらび（2〜5語）→ 🎟️1枚消費 → 執筆中（非同期・約1分）→ 待ち時間は みつける／たんけんへ誘導 → 完成 → よむ
2. ショートカット（追加）：のったよ／しょうさい →「📚 この ことばで おはなし」→ その語を選択済みで ことばえらびへ（ゲストは登録ゲート経由）

## 4. 採用した分岐（2案比較の結論）

- **分岐1 ゲストの登録ゲート**: 案A（機能別コピーのボトムシート）を採用。摩擦が低く文脈を維持。案B（フル画面ウェルカム）は初回1回のみ価値提示要素として併用。
- **分岐2 はっけん中ローディング**: 案A（ヒット＝1段・速い）と案B（ミス＝2段）を**両方採用**。速さ差そのものを演出に使う。
- **分岐3 残高0の見せ方**: 案A（子には「おしまい」だけ・課金は保護者メニュー）を採用。
- **分岐4 再生成トリガー**: 案A（しょうさいから明示的に再生成）を採用。新規はっけん（消費）と 再発見（rediscovery）を画面で分離。
- **分岐5 おはなし入口**: 案A（ライブラリ起点）を基本に、案B（発見直後ショートカット）を併用。

## 5. 却下した案と理由

- **分岐1 案B（フル画面ウェルカムを常用ゲートに）**: 毎回出すと遊びの勢いを止め、離脱を招く。初回のみに限定。
- **分岐3 案B（残高0の瞬間に保護者ゲート→購入）**: 「遊びの最中に課金画面を出さない」原則と衝突。コンバージョンより安全・ブランド方針を優先。
- **分岐4 案B（のったよ直後に毎回「これでOK／かきなおす」）**: 3〜6歳に毎回「採否の判断」を強い、発見の喜びを削ぐ。再生成は意図的操作として詳細に置く。
- **みつける枯渇＝即「全部みつけた」専用画面のみ**: 子どもの手が止まるため却下。まず復習モードを挟み、保護者導線も提示するハイブリッドに。

## 6. プロトタイプへの反映内容

- しょうさい画面に **「🎨 べつの えに する」**（再生成・チケット不要）と **「📚 おはなし」**（ショートカット）の操作行を追加。
- **再生成 確認シート**（`sheet:'regen'`）を新設。`confirmRegen()` → `genRegen` フラグ付きで `hakkengen` 演出 → `finishHakken()` が再生成時は**チケット消費せず・件数を増やさず**しょうさいへ戻る分岐を追加。
- のったよ画面に **「📚 この ことばで おはなし」** を追加。`storyFromWord(word)` が当該語を `storySel` にプリセットして ことばえらびへ（ゲストは `authReason:'story'` で登録ゲート）。

> コード名はプロトの名残（`write`/`collected`/`discovered`/`genRegen`）のまま。ADR-0001 のリネーム（`trace`/`zukanWords`/`hakkenWords`/`rediscovery`）は本実装フェーズで適用。子ども向けUIコピー（「べつの えに する」等）はひらがなのままで良い。
