# 決定追補：はっけん出題制御の簡素化

- 日付: 2026/06/30
- 対象: decisions v1（20260630_1820）§2-B, §2-C, §2-D, §7
- 起点: Claude Code セッションでの仕様議論

---

## 変更点

### 1. 日次回数制限の廃止

**変更前**: たんけんに日次回数上限（`daily_hakken_max`）を設け、上限到達で「きょうの たんけんは おしまい」画面へ遷移。

**変更後**: 日次回数制限を撤廃。チケット残高のみで新規はっけんの可否を制御する。

**理由**: 制御の軸が「日次回数」と「チケット残高」の二重になっていた。チケット残高だけで十分であり、保護者が子どもの利用量を制御したい場合はチケット購入量で調整できる。

### 2. HAKKEN_WORDS（静的プリセット語リスト）の廃止

**変更前**: みつけるの出題プールは `prepared`（仕込みことば）→ `HAKKEN_WORDS`（静的プリセット配列）→ 復習モード。

**変更後**: みつけるの出題プールは以下の優先順:
1. 未収集の `prepared`（保護者が仕込んだ語）
2. 未収集の `shared_cache` 語（過去に誰かが生成済み = キャッシュあり）
3. 収集済みの語（review モード）

**理由**: ADR-0001 で「プリセット語」概念は本番では持たないと決定済み。実際の出題元は共有キャッシュに蓄積された語であり、静的リストは不要。

### 3. たんけんの重複ブロック廃止 → 再発見として通す

**変更前**: たんけんで `classifyTanken` が `dup`（ずかんに既存）を返した場合、「もう ずかんに あるよ」でブロック。

**変更後**: ずかんに既存の語は**再発見（rediscovery）**として書く画面へ進む。チケット消費なし。Reveal 画面で再発見であることを伝える。

**理由**: 再発見は「また なぞれる」楽しみであり、ブロックすべきではない。バックエンドの `executeHakkenGenerate` は既に再発見をチケット不消費で処理する設計になっている。

### 4. Reveal 画面の再発見表示

再発見時の Reveal タイトルを初回発見と区別する:
- 初回発見: 「みつけた！⭐」「あたらしい ことば はっけん！⭐」
- 再発見: 「また あえたね！😊」（復習モードと同じトーン）
