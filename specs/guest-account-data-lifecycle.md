## 目的

ゲスト時代に集めた「ずかん」エントリはサインイン後も確実に引き継がれ、逆にサインイン中に集めたエントリはログアウト後（ゲスト状態）には見えなくなるよう、ずかんデータのライフサイクルポリシーを実装する。

現状、ログイン前→サインイン後の「引き継ぎ」はクライアントのステートを触らないだけの見せかけで、サーバーに永続化されていない（リロードで消える）。また、ログアウト時に `localStorage` がクリアされず、共有デバイスで前のユーザーの収集物が残り続ける問題がある。

## スコープ

- 含むもの
  - ゲストの `localStorage` 収集物をサインイン成功後にサーバー（`hakken_entries`）へマージするAPIの新設
  - マージAPIは ADR-0003 の「おためしことば」（事前生成済み・共有キャッシュ投入済みの語）のみ許可し、それ以外は棄却する
  - 認証中は `localStorage` に書き込まない（ゲスト専用ストレージ化）
  - 認証後の初期化フローで「認証確認 → マージ → クリア → サーバーから取得 → 上書き」を直列実行する
  - ログアウト時にハードリダイレクトで全クライアントステートを破棄する
- 含まないもの（明示的な非スコープ）
  - ゲスト永続ID・マルチデバイス対応（今回の要求に対してオーバーエンジニアリングのため却下）
  - bfcache/戻るボタン対策（脅威モデル＝家族間の閲覧であり、悪意ある攻撃者を想定しないため見送り）
  - 「たんけん」「保護者メニュー」の認証境界変更（ADR-0003で確定済み、対象外）

## 不変条件

- `localStorage` はゲスト専用ストレージであり、認証中は一切書き込まれない
- マージAPIは事前生成済み「おためしことば」以外の word を受け付けない（サーバー側許可リストで照合し、それ以外は黙って棄却する）
- マージは `UNIQUE(user_id, word)` を利用した冪等な操作である（同じ語を二重にマージしてもエラーにならない）
- ログアウト後、ブラウザの表示は集めた語ゼロのゲスト初期状態に戻る
- ログイン後にリロードしても、マージ済みの語は消えない（サーバーに永続化されているため）

## API 契約（該当する場合）

```
POST /api/hakken/merge-guest-entries
Request:  { words: string[] }   // ゲストの localStorage に記録された語のリスト
Response: 200 { merged: string[] }  // 実際にマージされた語。許可リスト外は無視される
認証必須（ログイン済みユーザーのみ呼び出し可能）
```

## 受け入れシナリオ

各シナリオに一意の ID を付ける。テストはこの ID をテスト名に含めること。

### AC-001: ゲスト時代に集めた語がサインイン後も引き継がれる

- **Given**: ゲストとして「おためしことば」を1つ以上みつけている
- **When**: サインアップ/ログインする
- **Then**: ずかんにその語が表示され続け、リロードしても消えない

### AC-002: サインイン中に集めた語はログアウト後に見えなくなる

- **Given**: ログイン中に新しい語をみつけている
- **When**: ログアウトする
- **Then**: （ゲストに戻った）ずかんの表示にその語は含まれない。サーバー側のデータは保持されたままで、同じアカウントに再ログインすれば復元される

### AC-003: マージAPIは許可リスト外の語を棄却する

- **Given**: `localStorage` に「おためしことば」以外の語が含まれている（不正な入力や旧データ混入を想定）
- **When**: マージAPIが呼ばれる
- **Then**: 許可リスト外の語はサーバーに保存されない

### AC-004: 認証中はlocalStorageに書き込まれない

- **Given**: ログイン済みの状態で新しい語をみつける
- **When**: 収集操作を行う
- **Then**: サーバーの `hakken_entries` に保存され、`localStorage` には書き込まれない
