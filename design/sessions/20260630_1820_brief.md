# はっけん機能の画面・導線設計

対象: はっけん画面全体（分類・ランダム候補・生成・一覧）

## 現在の実装

### API エンドポイント

| メソッド | パス | 認証 | 概要 |
|---------|------|------|------|
| POST | /api/hakken/classify | 不要 | ことばの分類（NG / 辞書あり / 重複 / 仕込み済 / OK） |
| GET | /api/hakken/random?n=3 | 不要 | ランダム候補を返す（辞書外プールから） |
| POST | /api/hakken/generate | 要 | AI でテキスト説明 + 画像を生成し、ずかんに登録 |
| GET | /api/hakken/entries | 要 | ユーザーのはっけん一覧 |

### チケット経済（実装済み）

- 新規登録で50枚付与
- はっけん生成で1枚消費
- 再はっけん（同じ言葉で再生成）はチケット不要
- チケット残高0でも閲覧は可能（生成のみブロック、402エラー）
- 購入フローは未実装

### 画像生成

- OpenAI GPT Image API（gpt-image-1-mini）で生成
- 5種のスタイル: えほん / ほんわか / ポップ / やさしい水彩 / ずかん
- 画像は R2 に保存、/api/images/ 経由で配信
- 共有キャッシュあり（同じ言葉+スタイルなら再利用、チケット不要）

### クライアント側

- SPA ではなく Cloudflare Workers + Hono の SSR
- クライアント JS は TypeScript 文字列定数として埋め込み（バンドラなし）
- 画面遷移は JS で DOM を差し替える方式

### 既存の画面フロー（クライアント JS ベース）

トップ → みつける → なぞり書き → ずかん登録 → ずかん一覧 → 詳細
（はっけんは「みつける」とは別の導線として設計中）

## 技術制約

- Cloudflare Workers: リクエスト30秒タイムアウト、WebSocket 不可
- クライアント JS が文字列埋め込み: React 等のフレームワーク不使用。DOM 操作で画面を構築
- 画像生成は 5〜15秒かかる: ローディング UI が必要
- R2 からの画像配信はパブリック URL なし: /api/images/ 経由のプロキシ

## 前回のデザインからの変更・発見
