# ずかん簡素化 + みつける整理後の全体デザイン確認

対象: ずかん画面、保護者メニュー、みつけるフロー、はっけん準備画面

## 現在の実装

前回の decisions（20260630_1820）+ addendum（20260630_2100）以降、以下の大きな変更を実装済み:

### ずかん画面
- CATEGORIES 分類を廃止。収集した語を登録順にフラットグリッド表示
- ? マスク（未発見語の伏せ表示）を廃止
- ヒント機能（? マスクの語を表示する機能）を廃止
- カテゴリバッジを詳細画面から削除

### 保護者メニュー
- 「みつける と たんけん」セクション → 「『みつける』ことばの準備」に変更
- 「言葉を仕込む」→「言葉を登録する」に統一
- カテゴリ別進捗 → 習得数のみに簡素化
- 説明文: 「みつけるで出る言葉を事前に登録できます。未登録の場合は自動で選ばれます。」

### みつけるフロー
- 出題優先順: prepared（保護者登録語）> STARTER_WORDS（共有キャッシュ10語）> 復習
- prepared がある間は必ず prepared から出題（以前は51語に埋もれて2%の確率だった）
- STARTER_WORDS は共有キャッシュに確実に存在する10語: あり・いす・いぬ・くつ・くま・つき・ねこ・はな・ぱん・ふね

### はっけん生成
- チケット消費の判定を「定数リストに含まれるか」→「共有キャッシュにヒットするか」に変更
- キャッシュヒット → チケット不要、キャッシュミス → AI生成 → チケット消費
- サーバー側の DICTIONARY_WORDS（51語の静的リスト）を廃止

### 用語整理
- 「ひみつのことば」→ 廃止（子どもに語の出自を区別させない）
- 「仕込みことば / 仕込む」→「準備ことば / 登録する」
- 「カテゴリ分類」→ 廃止（将来再検討）
- DICTIONARY（51語）→ STARTER_WORDS（10語）

## 技術制約

- クライアント JS は TypeScript 文字列定数として埋め込み（テンプレートリテラル）
- バニラ JS SPA（React/Vue 等のフレームワークなし）
- 状態管理は `setState` + `render` の手動再描画
- CSS はインラインスタイルが中心

## 前回のデザインからの変更・発見

前回 decisions で設計された「ひみつのことば」中心のフローを大幅に簡素化した:

1. **子どもへの区別不要**: 「みつける」で出る語が保護者の準備か自動選択かは子どもに関係ない。UI から区別を排除
2. **ずかんのカテゴリ不要**: MVP 段階ではカテゴリ分類は過剰。集めた語が並ぶだけで十分
3. **? マスク不要**: カテゴリ廃止に伴い、未発見語の表示も不要に
4. **「仕込む」表現が意味深**: 保護者メニューの「仕込む」が特別な響きを持ちすぎる。「登録する」で十分
5. **チケット判定の簡素化**: 定数リストではなくキャッシュの有無で判定するのが自然

## 今回お願いしたいこと

ざっくばらんに意見を聞きたい。形式ばった設計ではなく、以下について率直な感想・改善案を議論したい:

1. **ずかん画面のフラットグリッド**: 登録順で並べるだけで十分か？ソートや検索があった方がよいか？
2. **保護者メニューの簡素化**: 学習記録が「習得数: N個」だけになったが、保護者として他に知りたい情報は？
3. **みつけるフローの出題ロジック**: prepared > STARTER_WORDS > 復習の順で良いか？
4. **STARTER_WORDS 10語**: 初めて触る子ども向けの最初の10語として適切か？
5. **全体の統一感**: 今回の変更で decisions v1 と乖離した部分のデザイン面での違和感がないか
