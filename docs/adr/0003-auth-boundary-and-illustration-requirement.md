# ADR-0003: 認証境界とイラスト必須化

## Status

Accepted

## Context

本稼働に向けたデータ整備で、以下の問題が判明した。

1. **「みつける」でイラストなしの言葉が表示されるケースがある**: ゲスト時の 401 フォールバック、STARTER_WORDS（クライアント側辞書プリセット語）、shared_cache 語のクライアント取得漏れの3パターン
2. **ゲストが保護者メニューで準備ことばを登録できる**: その語の画像生成にはチケットが必要だが、ゲストにはチケットがなく、「みつける」でその語が出題されるとイラストなしで表示される
3. **たんけんで自由に語を入力できるが、AI生成にはチケットが必要**: ゲストがたんけんで新規語を入力すると生成できない

これらは「イラストを必ず表示したい」という要件と、「みつける機能はログインなしでも最初に使ってほしい」という要件の間で矛盾を起こしている。

## Decision

### 原則: AI生成（チケット消費）が発生しうる操作はログイン必須

| 機能 | ログイン | 理由 |
|------|---------|------|
| みつける（おためしことば） | 不要 | 共有キャッシュに事前投入済み。AI生成なし |
| みつける（準備ことば + 共有キャッシュ語） | 必須 | キャッシュミス時にAI生成 + チケット消費の可能性 |
| たんけん | 必須 | 自由入力 → AI生成 + チケット消費 |
| 保護者メニュー | 必須 | 準備ことば追加 → 将来のAI生成を前提とする |
| ずかん閲覧 | 不要 | 既存データの表示のみ |

### おためしことば

ゲスト向けに事前生成済みの語を「おためしことば」と呼ぶ。現在の STARTER_WORDS（いぬ/うま/くま/さかな/すいか/つき/とり/ねこ/はな/やまの10語）に相当する。

- 共有キャッシュに事前投入（シード）する
- ゲストの出題プールはおためしことばのみ
- ログイン済みユーザーの出題プールには準備ことば + 共有キャッシュ語も加わる

### イラスト必須

はっけんしたことばは必ずイラスト付きで表示する。`image_url` が NULL のずかんエントリは不正状態。

- イラスト生成に失敗した場合はフォールバック表示ではなくエラー画面を出す（既に `hakkengenError` として実装済み）
- ゲストの 401 フォールバック（`image_url: null` の即席オブジェクト生成）を廃止する

## Alternatives Considered

| 選択肢 | 利点 | 欠点 | 不採用の理由 |
|--------|------|------|------------|
| ゲストでも全機能開放し、イラストなしをフォールバック表示で許容 | 実装が簡単。ゲストの体験範囲が広い | イラストがないとアプリの核心体験が損なわれる。フォールバック表示は品質が低い | イラストがアプリの価値の中心であり、「ないけど見せる」は本末転倒 |
| ゲストには一切「みつける」を使わせない | 認証境界が単純 | 最初に触ってほしい機能を体験できない。導入フローが弱くなる | おためしことばのキャッシュで解決可能 |
| 保護者メニューはゲストでも開放し、準備ことば追加時にログインを促す | 保護者が先に語を登録してから子どもに渡せる | 登録だけして画像生成されない宙ぶらりん状態が生まれる | 操作の途中でログインを求めるのは UX が悪い。入口でガードすべき |

## Consequences

**良い面:**
- 「みつける」で表示される語は必ずイラスト付きになり、アプリの核心体験が保証される
- 認証境界が明確な原則（AI生成 = ログイン必須）に基づき、今後の機能追加時にも判断基準が使える
- ゲストでも「みつける」を体験でき、導入フローが維持される

**悪い面:**
- おためしことば10語の画像を事前生成・シード投入する運用作業が必要
- ゲストの体験範囲がおためしことば10語に限定される（ただし導入体験としては十分）
- たんけんをログイン必須にすることで、ゲストの探索体験がなくなる
