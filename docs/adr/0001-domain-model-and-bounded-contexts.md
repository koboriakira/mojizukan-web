# ADR-0001: ドメインモデルとコンテキスト境界の定義

- **Status**: Accepted
- **Date**: 2026-06-30

## Context

もじずかんの機能が増えるにつれ、コード上の命名や責務の境界があいまいになってきた。`entries` と `hakken_entries` の二重管理、チケット判定ロジックの散在、プリセット語と共有キャッシュの概念の重複など。開発判断の拠り所となるドメインモデルを明文化する。

## Decision

### 4つの境界づけられたコンテキスト

```
┌──────────────────────┐       ┌──────────────────────┐
│  ことばあつめ         │       │  おはなし             │
│  （コアドメイン）      │  ───▶ │  （コアドメイン）      │
│                      │ 語一覧 │                      │
│  集約: ずかん         │       │  集約: おはなし        │
│  - 語をみつける       │       │  - 語を選ぶ           │
│  - 語をたんけんする    │       │  - 絵本を生成する      │
│  - なぞって書く       │       │  - 読む               │
│  - ずかんに入れる     │       │                      │
│  - ひみつのことば     │       └──────────┬───────────┘
│                      │                  │
└──────────┬───────────┘                  │
           │ 生成依頼                      │ 生成依頼
           ▼                              ▼
┌──────────────────────────────────────────────────────┐
│  AI生成（支援ドメイン）                                │
│  - テキスト生成 / 画像生成 / 共有キャッシュ             │
└──────────────────────────────────────────────────────┘
           │ チケット消費         │ チケット消費
           ▼                     ▼
┌──────────────────────────────────────────────────────┐
│  アカウント・経済（汎用ドメイン）                       │
│  - 認証 / canSpend / spend / フリーミアム制限          │
└──────────────────────────────────────────────────────┘
```

- **ことばあつめ** と **おはなし** は独立したコアドメイン。おはなしはずかんの語一覧を参照するが、ことばあつめ側には何も返さない一方通行（Published Language）
- **AI生成** は両コアドメインから呼ばれる支援ドメイン
- **アカウント・経済** はチケット判定（`canSpend`/`spend`）を集約する汎用ドメイン

### ことばあつめの3つの行為

| 行為 | 誰が準備 | 何をする | 結果 |
|------|---------|---------|------|
| みつける | 保護者が準備したことばを | 子どもが選ぶ | なぞる → はっけんへ |
| たんけん | 子ども自身がことばを | かな文字で組み立てる | なぞる → はっけんへ |
| はっけん | どちらの経路でも | ずかんに未登録のことばを | ずかんに登録する |

「はっけん」は動詞として両経路に適用できる。みつけるでもたんけんでも、ずかんに未登録のことばを登録する行為が「はっけん」。

### ことばのモデル

プリセット語という概念は持たない。あらゆることばが「はっけん」の対象。

```
ことば (Word)
  word: string（ひらがな）
  description: string | null
  illustrations: Map<Style, ImageURL>
```

- 説明文とことばは 1:1（スタイルに依存しない）
- イラストとことばは N:1（スタイルごとに存在しうる）
- emoji フィールドは廃止（プロト開発の名残）

### 共有キャッシュはインフラ層

共有キャッシュの有無はパフォーマンスにのみ影響し、はっけんの可否には関係しない。

- キャッシュヒット → 生成スキップ（速い）
- キャッシュミス → AI生成が必要（遅い）

保護者がことばを準備する際、キャッシュから候補を提案することはあるが、それは保護者の準備を助ける機能であり、はっけんの前提条件ではない。

### ずかんエントリ

```
ZukanEntry
  word: string
  description: string
  imageUrl: string
  createdAt: Date
```

### ユビキタス言語

| 用語 | 定義 | コード上の名前 |
|------|------|---------------|
| ことば | ずかんに入れる対象。ひらがなの文字列 | `word` |
| ずかん | ユーザーが集めたことばの一覧。集約ルート | `zukan` |
| みつける | 保護者が準備したことばを子どもが選ぶ行為 | `mitsukeru` |
| たんけん | 子ども自身がかな文字を組み合わせてことばを作る行為 | `tanken` |
| はっけん | ずかんに未登録のことばをずかんに登録する行為。みつける・たんけん両経路で発生する | `hakken` |
| なぞる | 文字の輪郭をなぞって書く行為 | `trace` |
| ひみつのことば | 保護者が仕込む誘導語 | `preparedWord` |
| イラスト | ことば × スタイルに対する画像 | `illustration` |
| スタイル | イラストの画風（ehon, pop, watercolor, zukan） | `style` |
| 共有キャッシュ | ことば×スタイルの生成結果をユーザー横断で保持するインフラ層の仕組み。はっけんの可否には影響しない | `sharedCache` |
| 再発見 | 既にずかんにあることばを再度生成すること | `rediscovery` |
| チケット | 生成に消費するリソース | `ticket` |
| 残高 | 現在のチケット数 | `balance` |
| 付与 | チケットを増やすこと | `grant` |
| 消費 | チケットを使うこと | `spend` |
| おはなし | ずかんの語を素材にAIが生成する絵本 | `story` |

### コンテキスト間の関係

| 上流 | 下流 | 関係 | インターフェース |
|------|------|------|----------------|
| ことばあつめ | おはなし | Published Language | 語一覧API |
| ことばあつめ | AI生成 | Customer-Supplier | 生成リクエスト |
| おはなし | AI生成 | Customer-Supplier | 生成リクエスト |
| アカウント・経済 | ことばあつめ | Conformist | `canSpend` / `spend` |
| アカウント・経済 | おはなし | Conformist | `canSpend` / `spend` |

## Consequences

- `entries` テーブルは廃止方向。プリセット語はコード定数または共有キャッシュの初期データとして扱う
- `addTicket(amount)` は `grantTicket` / `spendTicket` に分離
- `collected` → `zukanWords`、`discovered` → `hakkenWords` にリネーム
- `screen: 'write'` → `screen: 'trace'` にリネーム
- チケット消費ルール（キャッシュヒット時の消費有無）は別途ビジネス判断として決定する（本ADRのスコープ外）
- カテゴリ分類は現時点では持たない。後日追加可能
